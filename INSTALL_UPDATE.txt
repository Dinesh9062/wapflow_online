Wapflow Connect 1.4.13 — Windows / Mac Chrome / existing EC2 update

TWO downloads: Source ZIP and Chrome Production ZIP. Extract each ZIP first.
Source root: Wapflow-Connect/package.json. Chrome ZIP: manifest.json at its root,
already built for https://api.wapflow.online.

CHROME ON WINDOWS AND MACBOOK
1. Keep the same existing extension card and loaded folder if possible. Replace
   ALL files in that folder with ALL extracted Chrome ZIP files. Keep profile/storage.
2. chrome://extensions > Developer mode > Reload your existing extension.
   First install: Load unpacked > extracted folder directly containing manifest.json.
   Disable old duplicates. Chrome does not load ZIPs. Refresh web.whatsapp.com.
3. Diagnostics: extension/server 1.4.13, adapter 2026.10.11-dom-v16. Sign in to Wapflow.
   This is a Chrome extension, not Safari or WhatsApp Desktop.
4. On EACH Chrome profile/device, open the intended uniquely named contact once.
   If unverified, Settings OR schedule editor: Individual/Group > tick I confirm >
   Verify open chat. Keep a dated native message visible. Opaque IDs can be valid.
5. Settings: your own number with country code; Your mention name = your actual
   @name/emoji; timezone and DMY/MDY. Save. Awaiting Reply defaults to Their reply
   pending (last message sent). Choose My reply pending for last message received.
   Reading is not replying. Grace period applies; use 1 minute for a controlled test.
6. Auto Reply: Contact specific > tick verified contact > response > active days /
   All day > Enable rule > Save. Top bar must say Auto replies on. Request a NEW
   incoming after setup. Old history is not auto-replied to. The supplied JSON had
   autoPaused=true, zero enabled rules, zero verified bindings: correct these first.
7. Follow-ups are private tasks. Send reminder opens setup; future time + sending
   consent + Add to queue creates the outgoing message. Verify alone does not send.
   Saved/verified recipient need not stay open. Sent confirms delivery; Done separately
   completes the private task. Private task alerts alone are not recipient messages.
8. Defaults: account gap 30 sec, schedule/reminder contact gap 10 min and 3/day,
   50 total attempts/day, auto delay 10 sec. Auto-rule mode uses rule contact limits
   for auto replies. Quiet hours default OFF; saved ON remains ON. Sending status
   explains waits. No timing setting guarantees protection from WhatsApp restrictions.
9. Background sending ON; original Chrome profile/tab logged in, open, online, awake.
   Another chat/tab/browser can be in front. Closed/frozen/sleeping sessions cannot
   send. Exact due-second delivery is not promised. Mac notifications: check Chrome
   permission, macOS Notifications and Focus. Unknown: inspect WhatsApp before retry.

EXISTING EC2
Read docs/MACBOOK_AND_RELEASE_GUIDE.md for backup, upload, backend/admin restart
and verification commands. Update Source + Chrome together. Keep your ORIGINAL .env,
database, JWT/encryption keys and Chrome card. No new schema migration. Do not reset
DB, generate replacement keys or seed a demo. DNS/Nginx/TLS remain configured.

LOCAL WINDOWS SOURCE (only if you also use a local backend)
Extract Source into a NEW folder, copy ORIGINAL .env into Wapflow-Connect root.
PowerShell in that root:
  npm ci
  npm run db:generate
  npm run db:migrate
  npm run check:setup
  npm run typecheck
  npm run build
  npm run dev:api
Second terminal, same root: npm run dev:worker
Production Chrome ZIP connects to EC2, not localhost. For a localhost Chrome build:
  $env:WAPFLOW_API_ORIGIN="http://localhost:4000"
  npm run build -w @zfleet/extension
Load apps/extension/dist. Legacy @zfleet workspace/storage names remain compatible.

behavior. After installation, check one consenting recipient while another chat is open.
